# Справочник подготовленных данных

Этот файл описывает существующий каталог: файлы, поля, ключи и связи. Требования к приложению находятся в [спецификации](../automotive_book_of_changes_spec.md), способы подключения данных, обработка фотографий и запуск — в [ARCHITECTURE.md](../ARCHITECTURE.md), ход работ — в [TODOs.md](../TODOs.md).

Все JSON сохранены в UTF-8, версия схемы — 1.

| Файл | Содержание |
|---|---|
| `structure.json` | Фиксированная структура 8 × 8, порядок битов и значения осей. |
| `descriptions.json` | Названия групп и осей; в `results` — утверждённые тексты и характеристики всех 64 результатов. |
| `vehicles.json` | В `items` — название и год автомобиля, поисковая фраза для фотографий. |
| `photos.json` | В `items` — адреса снимков, источник, автор и лицензия, если известны. |
| `placements.json` | В `cells` — ссылки `vehicleId`, `photoId` и статус согласования для каждого кода клетки. |
| `questions.json` | Полный банк интервью: шесть осей, 24 утверждённых вопроса; структура и валидация — в ARCHITECTURE.md. К каталогу автомобилей не относится. |

## Ключи и поля

Код клетки: `RRR-CCC`. Слева направо `RRR` соответствует осям 1–3 спецификации, `CCC` — осям 4–6. Строки и столбцы перечислены в порядке `000` … `111`. В `structure.json` позиции 1–3 указаны отдельно для каждой триграммы.

Идентификатор вида `car-000-000` — постоянный ключ записи. Связь автомобиля и фотографии с клеткой определяется полями `placements.json`, а не вычисляется из имени идентификатора.

Поля `descriptions.json → results → код клетки`:

- `personTitle` — название архетипа.
- `personPortrait` — литературное описание человека.
- `twinExplanation` — литературное описание автомобиля.
- `technicalSpecs` — технические характеристики одной строкой: привод, двигатель и коробка передач базовой комплектации. Префикс «Техника:» добавляет галерея.
- `editorialReason` — внутреннее обоснование размещения; в карточке не показывается.

`resultUi.twinIntro` содержит общую вводную фразу перед названием автомобиля. Название и год автомобиля находятся в `vehicles.json → items → vehicleId`.

В `photos.json` поле `url` используется для плитки, `full` — для крупной фотографии, `source` — для ссылки на источник. Все 64 записи используют локальные файлы WebP в `assets/images/cars/`, пути считаются от корня проекта, где находится HTML галереи. Имена файлов соответствуют кодам клеток, например `000-000.webp`. Поля `source`, `author` и `license` сохранены; внешние ссылки служат сведениями об источнике, а не адресами загрузки изображения.

Параметры оптимизации, исходные файлы и технические правила отображения описаны в [ARCHITECTURE.md](../ARCHITECTURE.md#фотографии-и-отображение).

Отдельного поля гексаграммы в текущих данных нет; комбинация битов задана кодом клетки.

Все 64 размещения, литературные тексты и технические строки заполнены и согласованы. Каталог и тексты сохраняются при реализации приложения согласно спецификации.
